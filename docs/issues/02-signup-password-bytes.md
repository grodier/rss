## Problem

`signupFormHandler` in `internal/server/user.go` limits the password by **characters**:

```go
form.CheckField(validator.MaxChars(form.Password, 72), "password", "Password must not be more than 72 characters long")
```

bcrypt limits input to **72 bytes**, and `bcrypt.GenerateFromPassword` returns `bcrypt.ErrPasswordTooLong` above that. So a password of 72 characters or fewer that is over 72 bytes passes validation, `UserRepository.Create` fails, and the user gets a **500**. Examples: 30 emoji (30 chars, 120 bytes), or many accented characters.

Confirmed: posting `name=a&email=a@b.co&password=<30 × 😀>` to `signupFormHandler` returns 500 today.

`loginFormHandler` already does this correctly with `validator.MaxBytes(form.Password, 72)`.

## Fix

In `signupFormHandler`, replace the `MaxChars` check with:

```go
form.CheckField(validator.MaxBytes(form.Password, 72), "password", "Password must not be more than 72 bytes long")
```

Keep the `MinChars(form.Password, 8)` check as is.
