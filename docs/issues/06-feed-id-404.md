## Problem

`feeds.id` is a Postgres `UUID`. `feedHandler` (`internal/server/feeds.go`) passes the raw `{id}` URL param straight to `FeedRepository.GetByID`. For a non-UUID value like `/feeds/abc`, Postgres returns `invalid input syntax for type uuid` (SQLSTATE `22P02`). That error is not `sql.ErrNoRows`, so the handler calls `serverErrorHTML`, responds with **500**, and logs an error for what is just a bad URL.

## Fix

Validate the ID in the handler before querying. That is cheap, skips a DB round trip, and can be unit-tested without a database.

1. `internal/validator/validator.go`: add
   ```go
   var UUIDRX = regexp.MustCompile(`^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$`)
   ```
   Use a regex; do **not** add a new dependency for this.
2. In `feedHandler`, replace the `feedID == ""` / `// TODO: Fix this` block with:
   ```go
   if !validator.Matches(feedID, validator.UUIDRX) {
       http.NotFound(w, r)
       return
   }
   ```
   (The JSON `badRequestResponse` it uses now is wrong for an HTML page anyway.)
3. Optional defense in depth: in `FeedRepository.GetByID`, map a `*pq.Error` with `Code == "22P02"` to `ErrNoRecord`, the same way `users.go` maps `23505`.
