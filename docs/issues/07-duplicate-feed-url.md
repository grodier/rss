## Problem

`feeds.url` has a `UNIQUE` constraint (`migrations/00001_init.sql`). `createFeedHandler` (`internal/server/feeds.go`) calls `FeedRepository.Create`. For a duplicate URL, Postgres returns a unique-violation (`*pq.Error`, `Code == "23505"`), the repository passes it back unwrapped, and the handler responds with **500**.

## Fix

Follow the existing duplicate-email pattern (`psql.ErrDuplicateEmail` in `internal/psql/users.go` + `signupFormHandler`):

1. `internal/psql/errors.go`: add `ErrDuplicateFeed = errors.New("duplicate feed")`.
2. `internal/psql/feeds.go` `Create`: `var pqErr *pq.Error; if errors.As(err, &pqErr) && pqErr.Code == "23505" { return "", ErrDuplicateFeed }`.
3. `createFeedHandler`: on `errors.Is(err, psql.ErrDuplicateFeed)`, call `form.AddFieldError("url", "This feed has already been added")` and re-render `discover.html` with 422, the same way the existing validation-failure branch does. `discover.html` already renders `.Form.FieldErrors.url`.

Out of scope: redirecting to or subscribing to the existing feed. That belongs with the future subscriptions work.
