## Problem

In `migrations/00001_init.sql`, `feeds.site_url` and `feeds.description` are nullable (`TEXT` without `NOT NULL`). `FeedRepository.GetByID` and `GetLatest` (`internal/psql/feeds.go`) scan them into plain `string` fields. If either column is ever `NULL`, `Scan` fails (`converting NULL to string is unsupported`): the feed page returns 500, and one bad row breaks the whole `/feeds` list.

It's latent today only because `createFeedHandler` inserts `""`. It will bite as soon as feed fetching is added, a row is edited by hand, or a future insert passes NULL.

## Fix

Pick **one** approach and apply it consistently:

- **Preferred (smallest):** use `COALESCE` in both SELECTs:
  `SELECT id, url, COALESCE(site_url, ''), title, COALESCE(description, ''), created_at FROM feeds ...`
- Alternative: a new goose migration (`make db/migrations/new name=feeds_not_null`) that backfills `''` and adds `NOT NULL DEFAULT ''` to both columns. This is more invasive; only do it if you also want the schema to enforce it.

While there: `Feed.LastFetched` is never selected. Leave it alone (out of scope).
