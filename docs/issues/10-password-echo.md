## Problem

When login or signup validation fails, the page is re-rendered with the submitted password pre-filled:

- `internal/ui/templates/login.html`: `<input type="password" id="password" name="password" value="{{.Form.Password}}" />`
- `internal/ui/templates/signup.html`: same pattern.

The plaintext password ends up in the response HTML, where it can be cached, saved by browser extensions, or captured by proxies and logs. Standard practice is to never send a password back to the client.

## Fix

In both templates, remove the `value="{{.Form.Password}}"` attribute from the password input (keep the name and email values as they are).
